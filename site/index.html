pg_lens 🔬🐘

A blazing-fast, modern TUI for PostgreSQL observability.

A microscopic view into your PostgreSQL performance. pg_lens connects to a running PostgreSQL server (13+) and renders live activity in your terminal — or in a browser, via the built-in Web Lens dashboard. Inspired by pg_activity and btop, built in Rust with ratatui.

Eight lenses over one connection

Every lens is a focused view over the same live snapshot. Press 1–8 in the TUI to jump straight to one; the Web Lens matches each view in dedicated tabs.

Macro Lens

Instance vitals at a glance: connection saturation gauge, TPS with scrolling sparkline history, cache hit ratio, active sessions, deadlocks and temp-file counters, server uptime — plus a lock-table pressure gauge that turns yellow/red before you hit “out of shared memory”.

Micro Lens

Per-backend activity: state, wait events, running duration, and a status marker for blocked (B) and waiting (W) sessions, powered by pg_locks + pg_blocking_pids(). Enter opens the full SQL and the blocking chain (A→B→C, root blocker highlighted).

Blocks & Locks Lens

Real-time wait-for dependency tree showing exact blocker-to-waiter relationships, root blocker detection with descendant counts, lock-table capacity pressure gauge, and an active locks table by lock type and relation. Press p to toggle views.

Replication Lens

Every WAL sender/receiver (pg_stat_replication state, sync mode, replay lag in bytes and time) and every replication slot (active/inactive, retained WAL, wal_status, safe WAL size), with tiered yellow/red severity.

Schema Lens

Per-table pg_stat_user_tables counters and on-disk sizes on a separate slow cadence (default 60s), an honest N of M tables count, partitioned tables collapsed into one parent row, a Δ1h size-growth column, and Enter for the full table structure — psql’s \d, in pg_lens’s own style.

Estimated bloat is on-demand only: the queries are heavy, so they run when you press B (Shift+B).

Index Lens

A severity-ranked advisor for unused, duplicate and prefix-redundant indexes, with the verbatim CREATE INDEX as evidence and the stats-reset age in the footer. Also flags INVALID indexes left behind by a failed CREATE INDEX CONCURRENTLY.

Query Lens

Top normalized statements from pg_stat_statements: calls, total/mean time, rows, shared-buffer hit%, a temp-spill column and a full I/O breakdown in the detail panel. When the extension is missing or older than 1.8, the lens shows the exact CREATE EXTENSION steps instead of an error.

Progress Lens

Unified live progress monitor for long-running maintenance: in-flight DDL operations (CREATE INDEX [CONCURRENTLY], CLUSTER, ANALYZE) and VACUUM with visual ASCII progress gauges, current phase, and ETA.

And the things that catch incidents

  • Column Color System & Duration Severity — intuitive terminal color system where state colors are distinct, and time-based severity coloring is applied strictly to duration so you spot stuck transactions instantly.
  • Copy to clipboard over SSH (OSC 52) — press y to copy the full SQL query, verbatim CREATE INDEX definition, or table schema directly to your system clipboard from anywhere — works seamlessly over remote SSH sessions and tmux without needing X11 or Wayland.
  • Instant psql shell (!) — drop straight into an interactive psql console on the exact same connection and credentials at the press of a single key.
  • SSL / TLS connection inspection — pg_stat_ssl integration flags encrypted vs plaintext sessions with a 🔒 lock badge, surfacing cipher suite and protocol version in the session detail overlay.
  • Interactive Database Picker (d) — switch target databases on the fly within the cluster without disconnecting or restarting pg_lens.
  • Problem-transaction hunting — transaction-age column and headline for the oldest idle in transaction session, blocking chains with deadlock-cycle warning, and an orphaned two-phase-commit watch: the usual causes of XID wraparound and lock pile-ups.
  • Idle connection / connection-age census — the sessions the activity table normally filters out, ranked oldest-first: the diagnostic for the classic pool-exhaustion incident.
  • Vacuum health & XID wraparound — cluster and per-table vacuum age, live vacuum progress, and prepared-transaction watch.
  • Vitals trend arrows — Connections, Cache hit and Lock table compare against ~5 minutes ago with a 5% deadband, tinted only when the direction is the concerning one.
  • History time-scrubber (Web Lens) — hover the chart for that moment’s vitals, click to pin it, ←/→ to step tick-by-tick.
  • Resilient by design — if the database goes down you get an error banner, the last known data stays on screen, and pg_lens reconnects with backoff. The UI never blocks on the database.
  • Read-only mode — --read-only hard-disables cancel/terminate and the web admin endpoints server-side, not just in the UI.
  • Version-aware queries — dedicated query sets for PostgreSQL 13, 14+ and 16+.
  • Single static binary — no runtime, no dependencies; musl builds run on any Linux, including Alpine containers.

The Web Lens dashboard

pg_lens serve starts an HTTP server that streams the same snapshots over SSE to a browser: sidenav, database switcher, light/dark theme, full keyboard navigation, and optional bearer-token auth. The dashboard is embedded in the binary — nothing to deploy alongside it.

Install

Every command below is the one from the project README.

One-liner (macOS / Linux)

curl -fsSL https://dog-hero.github.io/pg_lens/install.sh | sh

# or read it first:
curl -fsSL https://dog-hero.github.io/pg_lens/install.sh -o install.sh
less install.sh && sh install.sh

Verifies the published SHA-256 checksum, installs into ~/.local/bin, needs no sudo. macOS (arm64/x86_64) and Linux musl (x86_64/aarch64). Re-run it to upgrade; PG_LENS_VERSION, PG_LENS_INSTALL_DIR and --dry-run are supported.

Homebrew (macOS / Linux)

# macOS — cask (prebuilt binary, no Xcode/CLT required):
brew install --cask dog-hero/tap/pg_lens

# Linux (Homebrew on Linux) — formula:
brew install dog-hero/tap/pg_lens

On macOS prefer the cask: plain formulas trip Homebrew’s source-build preflight, and the cask clears the Gatekeeper quarantine attribute itself.

Cargo (crates.io)

cargo install pg_lens_tui   # compiles; installs the `pg_lens` binary
cargo binstall pg_lens_tui  # prebuilt binary, no compile

The published crate carries the built web dashboard, so cargo install needs no Node toolchain.

Prebuilt binaries

# TAG = any tag from the releases page
curl -L https://github.com/dog-hero/pg_lens/releases/download/$TAG/pg_lens-$TAG-aarch64-apple-darwin.tar.gz | tar xz
./pg_lens-$TAG-aarch64-apple-darwin/pg_lens --mock

Or just use the one-liner above, which resolves the tag and checks the checksum for you.

Archives for macOS and Linux (amd64 + arm64) on the releases page, plus .deb and .rpm packages (package name pg-lens).

From source

git clone git@github.com:dog-hero/pg_lens.git
cd pg_lens
cargo build --release -p pg_lens_tui
./target/release/pg_lens --mock   # instant demo, no database needed

Requires Rust, edition 2024.

Run it

Terminal (Live TUI)

pg_lens --dsn "host=localhost user=postgres dbname=postgres"
pg_lens --mock            # instant mock sandbox, no DB needed

Web dashboard

pg_lens serve --listen 127.0.0.1:8080

pg_lens refuses to bind a non-loopback address without PG_LENS_AUTH_TOKEN set.

Compliance & Licenses

pg_lens licenses          # audit all third-party licenses

Verify third-party licenses and compliance directly in your terminal.
